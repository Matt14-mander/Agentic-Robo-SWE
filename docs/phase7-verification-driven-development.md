# Phase 7–9：验证驱动的机器人软件工程

更新：2026-10-28。承接 Phase 6 与 M2，优先证明专业验证对真实修复的作用，再扩展自动优化。

## 目标与范围

研究问题：相同模型、任务与总预算下，数值、动力学及行为反馈是否提高真实机器人 C++ 缺陷的
隐藏评测通过率，并降低错误补丁被接受的比例？公开合成题只用于开发，不代表真实缺陷泛化。

本轮在 M7.0 三项架构基础上实现 M7.1 结构化修复轨迹，为 M8 验证技能库准备证据。
四组公平消融运行器与统一失败分类已实现，使用公开 8 题做离线与 scripted smoke 验证。
M2 批量 LLM 实验、真实模型四组重复实验、真实缺陷采集、技能自动提炼、模型训练和性能优化尚未完成；
不因记录基础设施完成而宣称这些实验已完成。

实施状态：M7.0a/b/c 已实现，首轮离线、Linux 原生与容器验收通过；最终容器复测因 WSL
根文件系统只读而受阻，不能把首轮结果表述为最终版本的完整容器重验。具体环境、
镜像来源、测试数量和限制记录在 [M7.0 使用说明](phase70-workspaces-and-evaluation.md)。
下一项实验优先级仍为 M7.1。轨迹采用显式开关，运行协议要求各对照组一致启用；
结构、命令与限制见 [M7.1 结构化修复轨迹](phase71-structured-repair-traces.md)。
四组定义、共享预算、校准规则与执行入口见 [公平消融运行器](phase71-fair-ablations.md)。

## M7.0 实施约束

1. 保留现有 Domain Pack、公开 fixture benchmark 和无参数 CLI 的默认行为。
2. 外部仓库采用显式工作区上下文，不能把目标仓库路径覆盖到 Agent 的安装根常量。
3. 只读模式不执行 CMake、clangd 或目标代码；C++ 执行需要显式选择本地可信开发或容器镜像。
4. 隔离执行不继承宿主环境变量，不挂载私有评测目录，不提供网络或 Docker socket。
5. 私有 oracle 只处理数据，不加载候选代码。候选只产生观察值，不能自报 passed。
6. 最终评测由操作者调用，不暴露给模型；只向修复环路开放开发测试。公开示例不是隐藏集。
7. 原生/容器集成测试与模拟协议测试分别报告；缺依赖不能声称原生验收通过。

## M7.1 实验协议

四组依次为基础工具、加领域文档、再加专业工具、再加开发验证反馈。各组共享相同模型、
任务划分、初始源码、最终隐藏评测器与预算，并记录实际 token、工具调用和壁钟成本。
不使用 focused/general 的整体差异替代单因素消融。先完成 8 题 smoke/重复基线，再运行
固定 Linux 环境下的完整 17 题；重复次数不是独立题目数。小样本结果报告不确定性，
不预设必须取得某个提升百分比，也不为提高分数放宽门禁。

结构化轨迹在四组中使用同一配置，作为观测设施，不新增模型提示词、技能检索或工具权限。
每次尝试保存独立运行标识、case/repeat/attempt、模型/环境/工具链标识、源码边界指纹、
公开 Agent 陈述、工具请求/结果、公开开发验证与用量。最终评测留在操作者报告中。
批次内并发调用不得伪造先后因果；缺失源码、截断、环境错误、未结束节点必须显式标注。
轨迹基础设施、四组运行器与统一失败类别已实现；首个适配器为公开 8 题，尚未接入独立隐藏题。
精细领域指标扩展、17 题完整套件中其余 9 题适配与真实模型重复实验仍需完成；smoke 不计为修复能力证据。

## M8 技能库实施顺序与边界

1. **M8.0a 证据与反例**：统一开发侧编译、Jacobian、动力学、仿真诊断；建立与源码及环境
   绑定的验证义务，缩减反例；不能把任意工具返回或 Agent 自述当作通过证明。
2. **M8.0b RepairSkill 原型**：先选择 Scalar/ADL、Jacobian 布局、单位/时间步等 3–5 类模式。
   从完整开发轨迹提炼候选，保留适用/不适用条件与证据引用；另用开发回归验证后晋升。
   生命周期为 proposed → validated → deprecated/revoked，失败经验可以保存但不能标为已验证修复。
3. **M8.1 审计**：对错误技能、依赖升级后的技能和不匹配上下文运行负例，检查回归与撤销。
4. **M8.2 冻结对照**：技能来源集、准入验证集、最终测试集分离；记录技能库版本和采集成本。
   先测检索迁移，再测多假设搜索，避免同时改变记忆、搜索和预算而无法解释收益。

DomainPack 继续提供人工定义的工具、领域规则和验证器；RepairSkill 是从开发经历中提炼、
经过验证的修复经验；源码 RAG 与答案缓存不承担技能准入职责。技能中的指令是待审查数据，
不能授予新权限、改写最终 oracle 或绕过工作区边界。执行程序与检查器可以成为技能附件，
但每次复用仍须检查前置条件与当前源码，不能直接重放旧轨迹或沿用旧通过结论。

RAX/ASPIRE 启发的是无需权重更新的经验积累及程序化流程；对本项目真实 C++ 修复的收益
仍是待验证假设。该方向前移到 M8，SFT/RLVR 留在 M9；不转向机器人策略训练或硬件探索。

## 技术路线依据

- [RoboBugBench](https://arxiv.org/abs/2610.16369)：机器人行为评测与 oracle 审计已有直接相关工作。
- [SWE-bench Science](https://arxiv.org/abs/2608.19799)：领域提示的效果需要任务级对照。
- [AlphaEvolve](https://deepmind.google/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/)：参考候选生成、自动评价与演化选择闭环。
- [clangd](https://clangd.llvm.org/design/compile-commands)：C++ 语义解析以真实编译参数为基础。
- [ASPIRE](https://arxiv.org/html/2607.00272v1)：参考细粒度失败证据、验证修复的技能提炼与不同策略搜索。
- [RAX](https://arxiv.org/html/2610.22496v1)：参考探索过程的程序化、技能适用条件与执行证据，以及前后端边界。

实施状态、操作命令与实际验证结果见 [M7.0 架构使用说明](phase70-workspaces-and-evaluation.md)。
